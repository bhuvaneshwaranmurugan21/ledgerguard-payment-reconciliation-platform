# ADR 0018: Independent reference oracle

## Status

Accepted for Part 2 Stage 2.

## Context

The accepted Part 1 contracts define financial behavior, but schema validation and documentation
cannot independently verify a runtime implementation. Reusing production calculation helpers in
expected results would allow the same defect to appear on both sides of a comparison.

## Decision

Implement the reference oracle in the separate `ledgerguard_reference_oracle` package. The package
uses independently written pure functions and frozen data authorities. It may share contract data,
but it may not import production reconciliation code. Production runtime modules may not import the
oracle. Only tests and validation tooling may compare the two namespaces.

The oracle returns admission decisions and expected financial values. It never writes operational
state or emits an authoritative proof. Admission and execution failure expectations explicitly
carry no authoritative output.

Use checked signed 64-bit arithmetic at each operation, exact reference allocation, deterministic
source ordering, frozen reason ordering, and canonical content identities. Validate the package
against hand-authored frozen examples and coherence vectors rather than fixtures generated by the
oracle itself.

## Consequences

The implementation duplicates some low-level canonical and arithmetic behavior by design. That
duplication is the cost of independence. Static import checks, adversarial cases, semantic mutants,
two clean exact-toolchain runs, and immutable CI evidence make the separation enforceable.

This decision does not implement production admission, transaction or settlement reconciliation,
proof storage, failure recovery, Spark parity, or AWS execution.
