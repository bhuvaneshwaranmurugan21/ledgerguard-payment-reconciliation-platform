# Part 1 requirement and gate authority

## Purpose

Corrective workstream C1 turns the frozen Part 1 audit into deterministic, bidirectional
authority. It answers four questions without changing the audit verdict: what was required, what
evidence was considered, who owns each unresolved correction, and which work remains.

Part 1 remains `PART1_CORRECTION_IN_PROGRESS`, the project remains `PROJECT_IN_PROGRESS`, and Part
2 remains `BLOCKED`.

## Generated authorities

`tools/build_part1_requirement_ledger.py` deterministically produces and checks three files:

- `spec/part1-requirement-ledger-v1.json` contains all 331 requirements in original order. Every
  row carries the original text and lines, rule references, contract/schema paths, documentation,
  tests, candidate and authority evidence, baseline verdict and rationale, correction owner,
  correction action, amendment linkage, resolution state, and final-audit requirement.
- `spec/part1-requirement-reverse-index-v1.json` independently indexes every forward dimension.
  Candidate evidence is partitioned between mapped evidence and exact explicit dispositions; an
  item cannot be in both sets, and their union must equal the Phase 4 evidence registry.
- `spec/part1-gate-registry-v1.json` contains exactly `OP-GATE-R001` through `OP-GATE-R014`, in
  order, with baseline and effective state, ownership, and final-audit requirement.

Generated bytes are checked into source control. `--check` regenerates the files in memory and
fails if checked-in bytes differ.

## Resolution semantics

The resolution layer reports correction routing, not a new conformance verdict:

| Resolution | Count | Meaning |
|---|---:|---|
| `PRESERVED_PHASE8_PASS` | 235 | The immutable Phase 8 result was `PASS`. |
| `FORMALLY_AMENDED_C0_PENDING_FINAL_AUDIT` | 8 | C0 established an approved replacement authority; C7 must still adjudicate it. |
| `C1_LOCALLY_ADDRESSED_PENDING_FINAL_AUDIT` | 4 | C1 provides the missing authority or traceability; C7 must still adjudicate it. |
| `CORRECTION_REQUIRED` | 84 | Implementation work is mechanically assigned to C2–C7. |

All 96 historical non-pass requirements require the final C7 audit. The 84 implementation items
are derived solely from `resolution_state == CORRECTION_REQUIRED`; they are not hand-maintained.

## Failure behavior

The C1 validator fails closed on source or generated digest drift, missing or duplicate
requirements, empty forward mappings, reverse-index divergence, undisposed evidence, incorrect
gate inventory, hand-edited remaining work, C0 history drift, contract drift, active completion
claims, or evidence mismatch. It first reconstructs and executes the exact C0 accepted tree, so
active C1 changes cannot silently invalidate the prior corrective checkpoint.

## Operational boundary

C1 performs repository-only authority work. It does not call AWS, dispatch an AWS workflow, mutate
infrastructure, add reconciliation runtime, change historical v1 or accepted v2 schemas, rewrite
Stages 0–4 or C0, claim Part 1 completion, merge its draft pull request, or unlock Part 2.
